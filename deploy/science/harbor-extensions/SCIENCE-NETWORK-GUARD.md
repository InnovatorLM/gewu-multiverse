# Experimental Science verifier process guard

`science_guarded_ack.ScienceGuardedACK` is opt-in and is not installed in the production launcher. It wraps every verifier `exec` entry point with `no_network_exec.py` when the task requests `no-network`. Runtime public networking remains unchanged. No upstream task or verifier is edited.

The launcher validates the Linux x86_64 audit architecture, rejects x32, closes non-standard inherited descriptors, refuses socket-backed standard descriptors, enables no_new_privs, and installs an inherited seccomp filter. Socket/socketpair, io_uring and cross-process descriptor/memory acquisition are refused. Local host tests exercise child exec and normal file I/O; an ACS probe exercised socket families, io_uring and child inheritance.

This enforces process-tree socket creation restrictions, not Pod-wide networking. It requires a fresh dedicated verifier with no untrusted background services or sidecars. Reused pools and unsupported architectures are refused. Shell startup before the trusted wrapper, artifact destinations, inherited process state, full result collection and original task numerical behavior still require integration review. The original ACK adapter remains unchanged. Do not claim complete no-network task validation from the capability probe alone.

Current evidence lives privately under `.state/harbor-eval/`: `netns-probe-4043d7a8.json`, `seccomp-local-validation.json`, and `guarded-ack-local-check.json`.

The experimental adapter now restricts verifier upload destinations to `/workspace/stacking_submission`, matching only the selected frozen stacking task. Absolute normalized paths are required; symlinks and special files in host upload trees are refused. Local checks cover valid artifacts, root-home overwrite, traversal, relative paths, and symlink rejection. Other Science tasks need their own reviewed artifact roots before this adapter can be reused.

Hardening requires non-privileged execution, no privilege escalation, and a read-only root filesystem. The original verifier requires CHOWN, FOWNER, DAC_OVERRIDE, SETUID, SETGID and KILL; ACS rejects explicit addition of these capabilities, so the revised adapter preserves platform defaults rather than overriding capabilities; the effective operations require live verification. Fresh writable emptyDir mounts cover /tmp, /logs, /workspace and /tests. A trusted init container using the exact pinned verifier image copies its original /tests into the private tests volume, permitting the original chmod without changing test bytes. It never mounts submitted artifacts. Tests use tests_materialization=environment; live uploads to /tests are refused. The earlier zero-capability ACS probes passed socket and file-transfer checks but did not cover the original verifier's user switching and therefore do not validate this revised configuration. Full Science task validation remains pending.

Revised ACS integration probe `guarded-permissions-d131034e` passed original-style root chown/chmod, subprocess UID/GID downgrade, root result readback, hidden-file denial for the nonroot child, inherited socket denial, immutable root, and artifact upload/download. This probe uses synthetic permission fixtures only, not a benchmark task or model score. Original-image test seeding and the complete Science verifier still require the real task run.

Real upstream verifier image probe `original-image-probe-32573d47` subsequently passed original test-file hash checks, permission operations, hidden-file denial, complete verifier evidence collection, and confirmed cleanup (known Pod 404 and two empty queries across all four resource kinds). This is still an infrastructure probe, not a full task result.

For planned expansion, `artifact_profile` accepts only reviewed upstream task names: stacking-disorder-diffraction (default), nanoindentation-property-extraction, eeg-erp-recovery, and certified-sparse-regression. Each profile permits only its original declared artifact paths. The two /app profiles additionally seed the original verifier /app into a writable volume. Local boundary checks pass; the additional profiles still require their own real-image ACS and model trials. Never infer those results from the default profile's probes.

Harbor also transfers its conventional `/logs/artifacts` directory for every task. The adapter permits that directory, while continuing to reject `/logs/verifier`, `/tests`, and arbitrary destinations. A regression invokes the real Harbor ArtifactHandler to transfer both convention and declared outputs. The first real Science attempt (`science-stacking-8091fed84c`) hit the 600-second agent budget and then exposed this missing conventional-path allowance; it produced no verifier score and is not a successful chain validation. Its resource cleanup and exact-secret scan passed. A designated DawnFM live probe confirmed `tool_choice=required` returns a bash call; this avoids the repeated no-tool-call responses observed during that attempt. A fresh full trial is required after the integration fix.

The second attempt (`science-stacking-abd6057378`) collected all original verifier evidence: five tests ran, one passed and four failed because no solver script was submitted. Reward was zero, and the agent still hit its 600-second budget. Required tool choice did not eliminate long-run no-tool feedback; the minimal probe is not evidence that it does. Cleanup and exact-secret scan passed, but the strict procedural gate remains false because of AgentTimeoutError. A bounded follow-up increases agent time to 1200 seconds and per-response output to 8192 tokens, retaining the same task, model and 2c4g profile.

`deploy/science/audit_public_benchmark_run.py` performs private post-run checks. Source the designated DawnFM env without tracing, then supply `--run-dir`, `--guard-report`, and `--out` paths inside the workspace. It refuses a live result or a guard report from a different run, enforces private artifact modes, scans exact credential values and their base64 encodings without printing them, checks configuration and trajectory model identity, and records token/API/tool usage and original CTRF test counts. A zero reward can pass the procedural gate; missing evidence, no executed tests, any trial error, credential matches, provider mismatch, or unconfirmed cleanup cannot. The scanner checks known credentials; it is not proof against every possible secret encoding or semantic leak. The gate is an evidence summary, not scientific acceptance or startup approval.
