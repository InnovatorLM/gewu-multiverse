# Independent scientific task-value review

Decision: **do not use the current EIS draft as the first accepted science task;
do not spend live difficulty-evaluation calls on this version.** Retain its
frozen package/images as a mathematical-interface and infrastructure regression
fixture. Previous independent interface/prototype approvals remain correctly
scoped; they never approved scientific value or benchmark difficulty.

The independent read-only reviewer used the frozen package's public inputs and
reference code, without model calls, network access or ACS. It reported three
local fits per case: approximately0.056seconds for the five-point ambiguous case
and0.100seconds for the nine-point excluded case. These reported repeats are
not separately retained as a machine-readable run receipt; the repository's
retained public-only reference study already provides reproducible input/code
hashes and a separate local execution. No target-model success rate is inferred.

The core remains a low-dimensional ideal Debye fit plus execution of the full
algebraic certificate supplied by the instruction. At nine observations there
are only84triples; the valid[0,1,3]certificate is the second lexicographic triple.
The fitted pair's Dvalues are approximately[0.126,843.805,582.819]; two useful
measurements have the same synthetic cost and are far from the decision boundary.
Nearly all observation tolerance remains unused by the two-branch fits. These
facts show an easy numerical kernel and weak scientific decision tradeoff;
they do not prove actual LLM performance.

Noisy-bound interpretation, arbitrary feasible witnesses and exact grading are
fair for the stated interface. Their correctness does not establish a practical
scientific problem. Ideal noiseless centers, uncalibrated bounds/costs and generic
parameter boxes lack a validated experimental application. Existing literature
supports careful distinctions about identifiability but not this fixture's
specific physical interpretation or acquisition assumptions.

## Next scientific proposal gate

Choose an actual scientific decision and explain how its result changes an
experiment or conclusion. Source frequency/error/cost assumptions from applicable
experimental conditions or instrument specifications; synthetic data remain
allowed with explicit provenance. Determine scientifically necessary nonidealities
with primary references or domain review, rather than adding mechanisms merely
for complexity. Define whether the target is contrast construction, robust
prediction or model exclusion and independently validate that decision's fairness
and solvability. Submit that revised scientific proposal for value review before
implementation or live difficulty trials.

Adding output steps, removing necessary formulas, tightening precision, hidden
parameter gaps or increasing data volume alone is not an acceptable redesign.
The current draft stays disabled. Optional Oracle authorization would validate
its infrastructure lifecycle only and would not change this scientific decision.
