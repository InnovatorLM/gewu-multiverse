# 启动与首题入库：两个里程碑

当前没有合格首题。这不等于 ACR/ACS 不通，也不能靠增加基础设施检查次数解决。
以下是执行顺序，不是验收通过记录；以实际运行证据为准。

## A. 角色启动就绪

- 已有证据：Shanghai 公网 ACR → Beijing ACS 镜像启动、指定 DawnFM
  模型调用、角色文件/凭证边界、受保护分支、UI 启停及资源释放检查。
- 出网允许；不得宣称网络隔离。继续保护控制面凭证、私有评审材料和 solver 输入边界。
- 再启动前检查当天队列额度、当前角色进程和 ACS 残留。保留现有额度配置；
  不能绕过已用额度或把模型任务改称基础设施检查。
- 作者可先研究提案；未被科学价值审查接受的方向不构建新镜像、不消耗难度评测额度。
  evaluator 对明确版本给反馈；curator 不接收未经完整审核的题目。
- 启动角色不表示首题已通过，不表示可开展全量生产评测。

## B. 首题正式接收

1. 原创科学提案：明确实际科学决策、第一手来源/许可、可用输入、
   难点和可执行评分合同。先审科学价值，再实现。当前 EIS 和传感器
   方向均未通过此关；原因见 proposals 下的方向决策文档。
2. 独立实现检查：标准 Harbor 包、正确参考输出、错误和等价解控制、
   依赖及镜像审计。固定候选 commit、输入和镜像 digest。
3. 真实全链路：干净 solver 环境、verifier 执行、私有轨迹留存及版本绑定，
   结束后确认本轮 Pod/Sandbox 等资源释放。镜像 smoke 不替代此项。
4. 独立质量评价：与两个固定版本 benchmark 对标，完成任务及轨迹的
   direct/WinRate 路线，并核实评审中的事实。结构合法和引文存在不等于结论正确。
5. 难度验证：指定 DawnFM/deepseek-v4.1-flash-1017，报告有效样本数、
   正确率、token 和工具调用数；基础设施失败单列。目标低于 30%，
   整体低于 50% 可接受；单次 trial 不能证明总体正确率。
6. evaluator 形成脱敏、精确版本绑定的结论，curator 核验身份、权限、
   证据及当前审批，准备 registry 条目和回滚目标。现有 private inventory
   只是材料索引，不是签收或批准；认证签收接入仍待完成。
7. 首题完整材料准备后取得用户最终批准，再按受保护分支流程接收。

## 当前应避免的工作

不要为已否决的科学方向继续堆叠发布包装；不要重复成功的基础设施测试
来代替缺失的科学验证；不要把候选资料清单、计划或诊断结果计为验收通过。
新的参考解执行须遵守当前 evaluator 指令的明确授权要求。
